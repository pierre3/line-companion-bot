# レビュー運用ルール（LineCompanionBot）

`line-dotnet` リポジトリのレビュー運用（`docs/REVIEW-WORKFLOW.md`）を踏襲するが、このリポジトリは
`Line.OpenApi.*` パッケージの**消費側**であり、OpenAPI 仕様の取り込みや Kiota 生成は行わないため
仕様レビュアー（spec-reviewer）は対象外とし、**3 役**に縮小する。

## 方針

- **3 つのレビュアー役**を、実装完了後のゲートとして設ける。
- 各レビュアーは**サブエージェント**として独立コンテキストで自動実行し、結果を集約して報告する。
- **最終的な go / no-go 判断は人（小林さん）**が行う。
- 実装完了時点で必ず先にレビューゲートへ回す（実装→コミット→マージを先行させない）。

## レビュアー役と担当

| 役 | 主な観点 | サブエージェント |
|---|---|---|
| コードレビュアー | DI配線・ファサード利用・Webhook処理・公開エンドポイントの使い勝手 | `code-reviewer` |
| セキュリティレビュアー | トークン保持/送出・Webhook署名検証・シークレット管理・認可境界 | `security-reviewer` |
| テスト・アーキ観点 | このアプリ固有の設計判断（インメモリ状態管理・IAPポーリング・notifier/pushフォールバック）の妥当性とテストカバレッジ | `test-arch-reviewer` |

## 記録

各ゲートのレビュー結果（判定・指摘・対応）は `docs/reviews/` に日付付きで残す。
